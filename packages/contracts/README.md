# Contribution contracts

[Schemas](schemas/README.md) are canonical draft 2020-12 inputs with unchanged v1 URNs. [Examples](examples/README.md) are synthetic, independent scenarios. All fifteen maintained schemas are compiled into a local Ajv 8.17.1 registry with ajv-formats 3.0.1. The twelve imported schemas remain byte-identical; private device-profile, storage-policy and power-policy contracts were added during implementation. Validation never fetches a schema over the network. Unknown URNs fail resolution; unknown schema names fail explicitly. UUID, date-time and URI format checking is enabled. The reviewed schemas currently use UUID/date-time; a separate formatter proof exercises URI as well.

`scripts/generate.mjs` uses json-schema-to-typescript 15.0.4 to generate all fifteen TypeScript projections. Its resolver rewrites local URNs only in memory and disables HTTP. `unknown` preserves declared additive payload uncertainty without `any`.

The compiler's unnamed nested objects lose ordinary sibling properties when `allOf` is present. `scripts/schema-projection.mjs` adapts only the in-memory compiler input: standalone `if`/`then`/`else` branches are excluded from static projection, and ordinary siblings beside remaining structural `allOf` become an explicit intersection branch. Schema metadata and definitions stay at the root. Required fields, enums, nullable objects and nested arrays therefore survive; structural `$ref` intersections remain. Mixed conditional branches that also declare ordinary structure fail generation explicitly pending a supported projection and proof. This is an adapter for the tested compiler, not a replacement schema compiler; canonical files are untouched.

Conditional relationships, `contains`, formats, numeric/string bounds, patterns and cross-record rules still require full Ajv validation. A structural TypeScript assignment does not prove runtime validity or authorization. The runtime registry enforces the original schemas, and engine response constructors validate before returning. Strict validator keyword checks fail on unsupported constructs. Do not weaken canonical JSON to accommodate static types.

`contracts:types` checks valid intent/effect/availability literals and typed field access, plus thirteen expected compile errors for missing fields, malformed nested objects/arrays, wrong enums/types and undeclared intent keys. A separate compiler fixture proves ordinary siblings and unconditional enum refinements survive structural `allOf`, including nullable array elements. The regression fails against the initial S0 outputs and passes after regeneration. All twelve projections were inspected: the three structures that lost fields were operation intent, effect entries and device-status availability entries; seven output files regenerate through direct or referenced conditional shapes. [The repair record](../../docs/verification/s0-projection-repair.json) distinguishes this proof from the initial setup evidence.

The Swift `ResponseEnvelope` is a small checked Codable projection of response v1 plus the version result slice. Status/state enums are generated from the canonical response schema. Decoding requires all six envelope fields including explicit nulls, validates enums, nonempty identifiers, error/action shape, and all three response conditionals. `JSONValue` retains unknown envelope/error/action/result keys, nested arrays and explicit nulls during re-encoding. Numeric payloads use Foundation Decimal; values outside its supported range are not a qualified transport contract. No Swift projection or fixture claims to validate repository/device schemas or cross-record authority. The engine remains the runtime validation authority for those schemas and all product payloads.

`native:test` prepares the same nine positive and eleven negative envelope cases checked by Ajv, then exercises Swift decode/round-trip rejection and compares both development responses with the engine. The implementation's separate native IPC probes verify bounded authenticated service transport; these schema fixtures alone do not establish that boundary.

`version.json` supplies the application/interface/engine development identity through generated TypeScript, Swift and Xcode configuration. Static generated files are checked in; `check:generated` rejects drift. The private packages have no independent release versions.

Run the commands in [BUILD.md](../../docs/BUILD.md). Import hashes remain in [source-imports.json](../../docs/source-imports.json). No schema or example JSON remains under `docs`.
