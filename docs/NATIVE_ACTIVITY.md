# Native activity and operation detail

The macOS window keeps the existing three-column structure. The sidebar selects an enrolled repository, including shared-project setup rows from the [paired registry](PROJECT_REGISTRY.md). Activity groups uncertain, waiting, interrupted and failed work under **Needs attention**, accepted work under **Running or queued**, and successful/cancelled attempts under **Recent activity**. Filters combine repository, execution host, outcome, date and text. They apply to the latest 200 retained attempts, a limit shown in the view; the CLI remains available for exact operation lookup.

A selected project shows its configured branch, owner and pending work, along with timestamped/cached publication state. Remote refresh is explicit. Late responses for a previous repository or operation do not replace current detail. Run local checks selects that project's current local source. Push still requires a concrete preview showing project, branch, destination and exact commit.

Native Push and local-check admission now use the same private fsynced request journal as Devices. An uncertain reply keeps the immutable command, selection and request UUID. A visible reconciliation action retries that request. Another action cannot displace its private retained file. Closing the window does not cancel the service operation. Receiving a definitive service reply resolves client admission while the operation remains independently retained.

Run detail keeps source range, concrete failure reason, copyable repair action, gate and transport result separate. `inactive`, `not_run`, `skipped`, reused evidence, passed and unknown never share a passing label. Generic check details show command, profile, elapsed time and the matching log marker. Original project aggregate completion does not fabricate individual check passes.

The read-only AppKit log supports text selection, ordinary keyboard copying and an explicit Follow latest control. User scrolling pauses its visible snapshot, including while a bounded live tail rolls older lines out. Resuming displays the latest retained output; search creates a fresh filtered snapshot. Copy/export menu actions explicitly name the latest log. The implementation uses Apple's [live-scroll notifications](https://developer.apple.com/documentation/appkit/nsscrollview/didlivescrollnotification), including events from legacy mice that need not have a start/end pair. No animation is required for follow updates.

The activity projection and log controller have synthetic Swift tests; native compilation and existing request-journal tests are separate checks. Actual keyboard/VoiceOver, resize, menu/window and live scrolling remain GUI qualification. No permissions, notification delivery or installation were enabled by these builds.
