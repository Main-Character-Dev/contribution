# Original project landing

After reviewed adoption, `submit` can execute the existing clean detached native-task route for Mathy, Main Character, Roboty and Glass Alpha. The source must belong to the enrolled clone and pass its original source-ownership policy. Admission retains the committed range, Git ref and bundle before acknowledging the operation. The source workspace remains owned by its native task manager.

The service rechecks adoption fingerprints, source identity, clean primary/task state and the selected range before invoking the project's `scripts/worktree-land` with its explicitly registered Node/pnpm environment. It does not acquire a second outer primary lease: the original worker owns its existing flight/lease protocol. Push lease credentials and unrelated service-chat attribution are not inherited. An existing candidate's task attribution is passed back through the original entry point.

Mathy's explicit combined message goes through its existing `--message-file` route. Its original canonical receipt validator, selector requirements and successful native reconciliation remain mandatory. The other three projects retain their integration-only message/attribution and `validation_status: not_run` policies; generic message overrides are rejected. No publication follows landing.

Completion requires the original candidate-specific receipt validator, reachable landed Git identity, clean primary and original source-worktree completion guard. An exit code alone cannot establish integration. A nonzero exit after promotion may still be reconciled from that complete proof. Missing receipt, unsuccessful native reconciliation or a failed completion guard retains uncertainty and blocks replay. `runs reconcile` observes the original receipt/guard without rerunning the landing worker. Original project repair remains authoritative.

Current boundary: this route requires a clean native detached source at dispatch. Dirty task edits are preserved and reported with `ADOPTED_CAPTURE_REQUIRED`; the captured-snapshot/import route for adopted projects is still unfinished. Generic tasks already support committed capture with unrelated dirty work. Adopted two-Mac owner transitions remain blocked until all cooperating legacy writers, including older task checkouts, are fenced. The service does not manufacture a Codex-looking source path to bypass original eligibility.

`tests/adopted-landing.test.mjs` exercises the service against synthetic project entry points for all four policy families using disposable Git histories. It covers unchanged native ownership, explicit Mathy messages/selectors, separate lease ownership, post-promotion failure, retained receipts and completion-guard repair without duplicate integration. These tests verify adapter orchestration; they do not replace real-project worker parity, expensive project suites or live cutover qualification.
