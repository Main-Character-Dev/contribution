# Repository migration and policy preservation

This sanitized guide replaces the package's private maintainer migration context in the source repository. The original audit and exact historical source seams remain external; see [SOURCE_PACKAGE.md](../SOURCE_PACKAGE.md). Existing policies remain authoritative. S0 performs no live project enrollment or migration.

## Resolve live authority first

Before changing an adapter, inspect that project's current primary checkout, active branch, HEAD, instructions, hook owner, runtime pins, source attribution, selected gate, destination and pending operations. Historical paths, branch names, revisions and tool versions are evidence leads, never constants. A remote default branch, integration branch, validation base and PR base are different identities.

Discovering a folder is read-only. It does not authorize setup scripts, checks, hooks, network mutations, enrollment, or policy changes. Deduplicate linked worktrees by common Git-directory identity; independently cloned repositories keep separate host mappings.

## Policy distinctions to retain

| Adapter | Required invariant |
|---|---|
| Generic new project | Local development by default; safe isolated integration; explicit multi-commit metadata; no generated broad validation system |
| Mathy | Preserve trusted dispatcher ownership, policy-only landing, introduced-history protections, multi-date attribution where allowed, explicit combined message, native dependency reconciliation, cumulative pre-push selection and constrained receipt reuse |
| Main Character | Preserve Husky/runtime bootstrap, staged/ownership/document guards, integration-only landing with validation not run, cumulative risk-routed publication gate, strict-mode distinction, exact pushed identity and constrained reuse |
| Roboty | Preserve existing hook owner and worktree restrictions, approved author and one-date policy, integration-only landing, lightweight local push safety, and distinct explicit/launch/distribution activation |
| Glass Alpha | Preserve commit/lifecycle hooks, integration-only landing, one-date attribution, and inactive publication validator/hosted CI; enrollment must not activate deferred policy |

Read the exact current attribution allowlists and committer rules from each project. Do not publish personal identities from the audit or replace them with the current Git user. Mathy's attribution rule cannot silently become the policy of every adapter.

Keep live project definitions for input ownership, check selection, commands, deadline semantics, always-live checks, receipt age/environment constraints, maintained-release routes and final source checks. A check run in a dirty/current directory is not automatically proof of the exact pushed tree. Inactive, skipped, reused and passed remain distinct.

## Integration, leases and recovery

Preserve isolated candidates, declared source ancestry, exact provisional SHA/tree, author metadata, supersession, conflict parking, source guards and source-to-landed mappings. A dirty primary blocks mutation; it is not a cleanup request. A source that advances after submission remains newer work.

All primary writers must honor one compatible common-directory lease and landing-flight contract. Do not install a parallel Contribution-only lock that legacy writers ignore. Process identity includes start time. Keep native build/simulator resources scoped to their existing owners. A managed push and its hook adopt the same verified invocation lease without a blind skip variable or double-acquisition deadlock.

Post-promotion dependency/native reconciliation is a separate result. Retain `landed_reconciliation_failed` where the project uses it, and resume that stage against the recorded landed identity. Do not replay integration, erase the candidate, or reset primary to conceal a failed follow-up.

Allocate a distinct attempt/log before reporting; no competing request may truncate another's latest log. An existing run retains its original executable and policy. Migrate only after affected writers drain or their supported continuation is established.

## Adoption sequence

1. Reconcile the live seam with the dated private reference and record differences.
2. Add per-attempt reporting while preserving commands, ordering, selection, activation and exits.
3. Observe the outer deliberate Git invocation; run the enabled gate once inside it. Hook-only clients retain unknown delivery unless a supported completion signal exists.
4. Extract common supervision, runtime selection, coordination and evidence mechanics behind narrow adapters, retaining product checks locally.
5. Prove parity in disposable fixtures, then cut over one authorized repository at a time with compatible pending-state and rollback records.

Include contention, dirtiness, changed tips/bases, supported/unsupported ref transactions, attribution boundaries, unavailable dependencies, expected skips, inactive gates, lost replies and post-promotion failure. Use focused proof for each seam; real publication and expensive product suites are not default migration smoke tests.

## Two-Mac authority cutover

Before changing a canonical owner or availability mode, reconcile histories, candidates, receipts and active jobs. Record the chosen owner and branch, drain/redirect old writers, and turn the companion primary into a safe mirror. No automatic owner election follows lost contact.

Install a Contribution-owned publication-authority guard through the existing hook owner. Companion direct pushes must refuse before gate/transport with the supported managed-push route. They must not enqueue a remote push while also continuing the original push. This authority guard is separate from validation activation, including for an inactive gate.

Retain the guard or compatible refusal on rollback. Re-enabling companion publication requires an explicit reconciled ownership change. Revert only migration-owned configuration still matching the expected value, preserving concurrent changes. Rollback does not rewind branches, reverse a push, discard receipts, recreate native worktrees, or downgrade installed product data.

## GitHub and other services

Observe current rulesets, required checks, actual head/test-merge associations and existing PR automation. Do not assume a reviewer count, duplicate an auto-open workflow, reactivate CI, fabricate remote `main`, or rotate integration branches without the project's rule. Advisory failures stay visible without becoming invented merge blockers.

Do not move backup, restore, security, deployment or privileged PR workflows onto the Mini through migration. Unrelated launch jobs and Codex schedules remain untouched. An obsolete service is separate maintenance work, not material to import into Contribution.

## Roboty device adapter

Roboty is the first consumer of the shared module, not the owner of another device manager. Its existing update route retains source routing, exact build-input checks, scheme/configuration, toolchain, build numbers, bundle/team/entitlements, signing and activation policy. Resolve those facts live. Contribution supplies a qualified reusable backend through its installed versioned interface.

Keep the working local/native route. Expanding a network transport allowlist does not establish a trusted remote session. Prepare while offline, transfer an immutable verified artifact if hosts differ, and verify an actual in-place installed identity/build plus meaningful data and Keychain continuity.

Respect named native sessions and foreground/pending-operation guards. No implicit force-quit, uninstall, trust reset, robot action, product pairing migration, workspace-history merge, distribution activation or Git publication follows a device request. Product-to-Mac connectivity and Apple developer connectivity are separate acceptance domains.

Follow [D0–D4 and every RDEV requirement](08-REMOTE_IPHONE_DEVELOPMENT.md), including actual travel initiation, independent host provisioning, cold cellular, uncertainty and cleanup. Before removing duplicate helpers, establish a single owner for every retained source check, artifact validator, selector, lease, supervisor and receipt. A thin compatibility adapter is a valid first step. Rollback restores a compatible future local route after reconciliation without changing phone data or prior effects.
