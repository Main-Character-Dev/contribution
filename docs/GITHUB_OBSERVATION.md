# GitHub observations

The service observes the configured push destination through GitHub's supported REST and GraphQL interfaces. It reads credentials from the signed-in `gh` credential route for each request, holds the token only in memory, bounds pagination and response size, and respects primary/secondary rate-limit backoff. A failed current observation leaves last-known data visibly stale; auth, permission, ambiguous 404 and API failures cannot become green readiness.

The observation combines current PR head and explicit potential merge commit, current rulesets, classic branch protection, review decision and GitHub's own merge calculation. When the test-merge commit has reported checks/statuses, it is the evaluated commit. Required names shared by a check run and classic commit status require both. App-bound rules require verified integration identity. Classic status records without that identity cannot satisfy an app-bound requirement by inference. A required pending, missing or failing result blocks readiness; optional failures remain visible independently. Closed and merged PRs remain distinct outcomes.

Discovery covers recently created workflow runs, including scheduled and manual activity. Subsequent scans overlap the last successful observation by fifteen minutes; the first scan covers seven days. Older known active runs are polled individually. Attempts and timestamps prevent late observations from replacing newer runs. Each scan remains bounded: five pages and fifty older active runs. Exceeding a bound leaves observation incomplete, rather than silently omitting activity. This is a bounded activity view, not an exhaustive historical GitHub archive.

The native repository toolbar opens GitHub activity and a ready PR through ordinary GitHub links. Workflow jobs and steps are scoped to the selected immutable run attempt. The internal authenticated client routes are `github.jobs` (`repo`, `runId`, `attempt`) and `github.logs` (the same fields plus `jobId`); they are read-only supporting interfaces for the existing activity viewer, not publication commands.

Job logs are explicitly snapshots. An active job is `not_yet_available`; confirmed expiration is `expired`; auth/permission refusal is `denied`; ambiguous absence or transport failure is `unavailable`. Downloads follow only an HTTPS GitHub-storage redirect from the authenticated job-log endpoint, with no API credential forwarded. Temporary signed URLs are not retained. The service redacts output and returns at most the first 512 KiB with an explicit truncation flag. The native viewer supports search, selection, copy and the original GitHub link. No live GitHub log stream is implied.

Current proof is fixture-based: current/old head, test-merge precedence, same-name status/check, app identity, classic rules, idle discovery, older active runs, late attempts, pagination, API/auth/rate failures and bounded log states. The native viewer builds, but live credentials, visual interaction, remote notification delivery and repository-specific GitHub qualification remain separate work.
